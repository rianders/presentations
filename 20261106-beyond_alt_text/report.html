Testing AI on Handwritten Notes, Printed Notation and Diagrams: What We Learned

From Beyond Alt Text: Notation, Diagrams & Symbols, Rutgers UOES, November 6, 2026. Tests run November 3–5, 2026 by Rick Anderson.

In short

  • The prompt matters more than the tool. Asked only to “make this accessible”, tools changed the page or added answers to it. With a prompt that forbids solving or correcting, every completed run kept it as written.
  • “Accurate” can mean “correct it”. “Transcribe this accurately” kept a page’s mistakes in all three models. “Make this accessible and accurate” got the page solved in all three.
  • Don’t take the default model. In every tool the default model missed lines. The stronger model in the same tool did best, and two of the three best are in tools every Rutgers faculty member already has.
  • Send one page at a time, as images. Tall pages and PDFs read worse whole. Each tool also limits how many files it takes per message.
  • The best model still makes fluent, unmarked mistakes on specialized notation. Only someone who reads the notation can catch them.
  • Canvas’s tools help, but a score isn’t a check. Ally can draft a one-sentence description, and it scored a page 92% while the page’s math was being read aloud with “s” as “South”. Listen to the page yourself.

What we tested

This report covers both handwritten lecture notes and material made for testing. The handwritten notes are real course material: an algebra page and a graduate lecture. The short printed pages and diagrams were drawn or chosen for these tests, so we could write answer keys first.

The main handwritten test was one real page of college algebra from the Accessibility Sandbox course: 30 lines of worked problems, with colours, circles, cross-outs and a warning written in capitals. It contains five details tools tend to “fix”, among them:

  • a simplification written as 2x+9x2=2x+9x\frac{2x+9}{\sqrt{x^2}} = \frac{2x+9}{x}, which is true only when x is not negative;
  • the instructor’s note “DO NOT REWRITE NEGATIVE EXPONENTS!”;
  • an extra factor of (2x + 9) in one line that the later steps don’t use.

A faithful transcription keeps all of these exactly as written. We then ran a full 14-page graduate lecture on Markov chains, with state diagrams and derivations, through the two strongest models.

1. The prompt

A plain “Make this accessible.” corrected the square-root line in 6 of 8 runs across Gemini and ChatGPT, and in the other 2 made new mistakes in the math. Tools added “x > 0”, replaced the line with an absolute value, reworded the warning to “do not rewrite negative exponents too early”, or returned a cleaned-up image of the page that a screen reader cannot read. One said the notes themselves made the point, which they don’t.

This prompt kept the line as written in all 7 runs that finished:

Make this accessible. Do not solve, simplify, correct or finish anything.

Notation: the LaTeX, and how someone in [your field] would read it aloud.
Figure: what it shows, not what it proves.

Mark anything you were unsure of.

On a “find the mistake” worksheet, a tool that fixes the mistake has written the answer key. The first line of the prompt is what prevents it.

Your chat history made no visible difference: runs with no history or memory changed the page the same way. In ChatGPT, a Temporary chat still uses memory and custom instructions unless you switch it to Unpersonalized.

The wording did it, not the model: “accurately” about the copying was safe, and “accurate” about the page got it corrected. “Transcribe this accurately” isn’t enough on its own, though, because it returned plain text with no LaTeX, reading or description. A blank quiz with the plain prompt drew no answers in what we could read, but the tools changed it: one rewrote the instructions and added a hint, and another returned a picture of the quiz. Gemini failed to answer on the quiz.

3. Preparing the page

  • One page at a time, as an image. A PDF’s hidden text layer can scramble symbols and layout; an image of the page shows the tool what a person sees.
  • Cut tall pages into page-shaped pieces, in the white space between problems. Our test page is 4.4 times taller than it is wide. Read whole, it lost lines and one run quietly corrected a line; cut into four pieces, the same model got them right. Tell the tool the pieces are one page, in order.
  • Know each tool’s limits. Copilot Chat (Basic) takes 2 images per message. Gemini took 10 files and silently dropped the rest: given a 14-page lecture, it transcribed 9 pages and described them as “the 9 attached pages”.

4. A hard lecture, and the mistake only an expert would catch

The 14-page Markov chains lecture went to the two strongest models with the notation-access skill attached. GPT-6 Astra transcribed all 14 pages into one Canvas page: 157 equations in MathML, the original diagrams kept with descriptions, and 15 places marked as uncertain. Gemini 3.6 Thinking covered 9 pages and marked nothing as uncertain.

Both made the same mistake on pages 2 and 3, and neither flagged it. The notes write

Pij(n)P_{ij}(n), the chance of going from state i to state j at time n. Both models wrote Pij(n)P_{ij}^{(n)}, the chance of getting there in n steps: a different idea.

Read aloud, nothing sounds wrong. The mistake was found only because the instructor reads the notation. It was settled by looking at the handwriting, after the models had run.

  • One error sounded sure. Gemini wrote a field into a table that doesn’t have it, in tidy notation, with no doubt marked. One said so. Copilot left out the LED’s direction and marked that it was unsure.
  • A one-sentence label leaves out what a diagram says. On the map, Ally described “eight labeled regions (A–H) shaded in four colors”, with no region’s value.
  • These are easy cases. Expect worse from scans, handwriting, crowded circuits, and maps with real place names or rainbow scales.

6. Putting it in Canvas

  • Ask for MathML, with the LaTeX kept inside it, so a screen reader with MathCAT can read each equation and step through it.
  • Check what you get. One answer claimed to follow WCAG 2.2 AA and hid every one of its 30 equations from screen readers, with the readings collapsed out of sight. Naming the two problems fixed both in one revision.
  • Pasted into a sandbox page through the HTML editor, Canvas kept all 30 MathML equations, their LaTeX, the circles and cross-outs, and the colours. Copy and paste as UTF-8, or characters such as ’ and − arrive garbled.
  • Canvas’s own Immersive Reader button read the MathML aloud correctly in the two algebra equations we checked by ear, with no extra software. It reads each equation and then the written reading under it, so you hear it twice, and it clips ovals drawn around terms.
  • It isn’t always right. On one page with the sample standard deviation, Immersive Reader read “s” as “South”, in plain alt text and in MathML alike. We don’t know why. The rest of the formula’s structure came through in MathML: “square root of, sum from i equals 1 to n of …”.
  • An image with no description gives it nothing to read. The Canvas equation editor gave the same reading as MathML pasted into the HTML editor, with no HTML needed.
  • Ally can draft a description. In our Rutgers sandbox course, an image’s Ally dial opens a panel with “Auto-generate description”. It’s labelled as needing a check. On the formula it wrote a paraphrase that doesn’t say whether the root covers the “n minus 1”, and it doesn’t correct or transcribe a page of math.
  • Ally’s score checks that a description exists. A handwritten page with 30 equations scored 100% with a one-sentence description and no math. Canvas’s own checker flagged Ally’s drafted sentence as over 120 characters.
  • Signal code in words. A code block alone ran straight on from the equation, and “#” became “hashtag”. A lead-in sentence, a heading, and the results in plain sentences after it were all heard clearly. The code itself is still read as flat words.
  • If one image file is used twice, a description on one copy can show up on the other. We saw this once and don’t know the cause.
  • Not yet tested: listening to any of this with a screen reader such as NVDA, JAWS or VoiceOver.

What to do

  1. Use the prompt above, or the notation-access skill, every time.
  2. Switch from the default model to the stronger one.
  3. Send one page at a time, as images; cut tall pages into pieces.
  4. Check the output against the page yourself, starting with everything it marked as uncertain.
  5. For an assessment, decide yourself whether any note about an error stays in.
  6. Ask for MathML for Canvas, or use the equation editor, and listen to the page before students do. A checker’s score doesn’t replace that.
  7. Don’t ask a tool to make a page “accurate”. Say what must stay as written.
  8. Give the equation its context: what you’d say in the lecture. For code, say that it’s code and what it does.

Limits of these tests

One handwritten algebra page, one handwritten lecture, a few short printed test pages and five diagrams, generally one run per model, over three days. This is a demonstration, not a ranking: tools and models change month to month, and the same model can answer differently on another run. Gemini also failed to answer on several tries. Scores were checked by the author. Model names and limits are as of November 5, 2026.
